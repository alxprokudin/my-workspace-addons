# Тестирование и публикация дополнения в Google Workspace Marketplace

## 📋 Важные понятия

### Статусы публикации

1. **Testing (Тестирование)** — текущий статус
   - Дополнение доступно только тестовым пользователям
   - Не отображается в публичном Marketplace
   - Не требует верификации Google
   - Лимит: до 100 пользователей

2. **In Production (В продакшене)**
   - Дополнение видно всем в Marketplace
   - Требует верификации Google
   - Нет ограничений на количество пользователей

### Развертывание (Deployment)

Развертывание — это опубликованная версия вашего дополнения, которая:
- Имеет уникальную ссылку для установки
- Может быть доступна тестовым пользователям (при статусе "Testing")
- Может быть доступна всем (при статусе "In Production")

## 🧪 Вариант 1: Тестирование с тестовыми пользователями (текущий статус)

### Шаг 1: Создание развертывания в Apps Script

1. Откройте ваш проект в [Google Apps Script](https://script.google.com)
2. В левом меню нажмите **"Развернуть"** (🚀) → **"Управление развертыванием"**
3. Нажмите **"Создать развертывание"** (или **"New deployment"**)
4. В правом верхнем углу нажмите на иконку шестеренки ⚙️
5. Выберите тип: **"Add-on"**
6. Нажми**

### Шаг 2: Заполнение формы Store Listing

**Важно:** Даже для тестирования нужно заполнить все обязательные поля:

1. **Add-on name** (Название дополнения):
   ```
   Экспорт в Excel
   ```

2. **Description** (Описание):
   ```
   Экспортируйте активный лист Google Таблицы в формат Excel (.xlsx) в выбранную папку Google Drive
   ```

3. **Logo** (Иконка):
   - Загрузите иконку 128x128 пикселей (PNG)
   - Файл: `docs/icons/icon-export-excel-128x128.png`

4. **Screenshots** (Скриншоты):
   - Минимум 1 скриншот
   - Размер: минимум 640x400 пикселей
   - Формат: PNG или JPG
   - **Можно добавить временные скриншоты для тестирования, потом обновить**

5. **Support URL** (URL поддержки):
   ```
   https://alxprokudin.github.io/my-workspace-addons/
   ```
   или
   ```
   mailto:alxprokudin@gmail.com
   ```

6. **Privacy Policy URL** (URL политики конфиденциальности):
   ```
   https://alxprokudin.github.io/my-workspace-addons/privacy-policy.html
   ```

7. **Terms of Service URL** (URL условий использования, опционально):
   ```
   https://alxprokudin.github.io/my-workspace-addons/terms-of-service.html
   ```

8. **Category** (Категория):
   - Выберите: **Productivity** (Производительность)

9. **Language** (Язык):
   - Выберите: **Russian** (или English)

10. Нажмите **"Deploy"** (Развернуть)

### Шаг 3: Получение ссылки на развертывание

После создания развертывания:

1. В разделе **"Управление развертыванием"** вы увидите ваше развертывание
2. Нажмите на него, чтобы открыть детали
3. Скопируйте **"Installation link"** (Ссылка на установку)
   - Выглядит примерно так: `https://workspace.google.com/marketplace/app/...`

### Шаг 4: Добавление тестовых пользователей

1. Откройте [Google Cloud Console](https://console.cloud.google.com)
2. Перейдите в **"APIs & Services"** → **"OAuth consent screen"**
3. В разделе **"Test users"** нажмите **"+ Add users"**
4. Добавьте email-адреса тестовых пользователей
5. Нажмите **"Add"**

### Шаг 5: Установка дополнения тестовыми пользователями

**Отправьте тестовым пользователям:**

1. Ссылку на установку (из шага 3)
2. Инструкцию:
   ```
   Для установки дополнения:
   1. Откройте ссылку в браузере
   2. Нажмите "Установить" (Install)
   3. Выберите аккаунт Google
   4. Разрешите запрашиваемые разрешения (Google Sheets)
   5. После установки откройте любую Google Таблицу
   6. В меню должно появиться "Экспорт в Excel"
   ```

### Шаг 6: Проверка работы

Попросите тестовых пользователей:
1. Открыть Google Таблицу
2. Проверить наличие меню "Экспорт в Excel"
3. Протестировать экспорт листа
4. Сообщить о любых проблемах

## 🌐 Вариант 2: Публикация в Marketplace (для всех пользователей)

### Требования для публикации

1. ✅ OAuth Consent Screen настроен
2. ✅ Развертывание создано
3. ✅ Store Listing заполнен
4. ❌ Статус должен быть изменен на **"In Production"**
5. ❌ Требуется **верификация Google**

### Шаг 1: Изменение статуса на "In Production"

1. Откройте [Google Cloud Console](https://console.cloud.google.com)
2. Перейдите в **"APIs & Services"** → **"OAuth consent screen"**
3. В разделе **"Publishing status"** нажмите **"Publish app"**
4. Подтвердите публикацию

**⚠️ Внимание:** После публикации:
- Google может запросить верификацию
- Дополнение станет видно всем в Marketplace
- Ограничение в 100 пользователей снимется после верификации

### Шаг 2: Верификация дополнения

После изменения статуса на "In Production":

1. Google может автоматически запросить верификацию
2. Перейдите в **"Verification Center"** в Google Cloud Console
3. Заполните форму верификации:
   - Описание функциональности
   - Объяснение использования OAuth scopes
   - Видео демонстрации (рекомендуется)
   - Контактная информация

4. Отправьте на проверку
5. Ожидайте ответа Google (3-7 рабочих дней)

### Шаг 3: Публикация в Marketplace

После верификации:

1. Дополнение автоматически появится в [Google Workspace Marketplace](https://workspace.google.com/marketplace)
2. Пользователи смогут найти его через поиск
3. Можно будет делать скриншоты из Marketplace

## 📸 Скриншоты из Marketplace

### Можно ли делать скриншоты при статусе "Testing"?

**Короткий ответ:** Нет, при статусе "Testing" дополнение не отображается в публичном Marketplace.

**Альтернативы:**

1. **Скриншоты из ссылки на установку:**
   - Откройте ссылку на развертывание
   - Сделайте скриншот страницы установки
   - Это будет выглядеть похоже на Marketplace

2. **Скриншоты после публикации:**
   - Измените статус на "In Production"
   - Дождитесь появления в Marketplace (может занять несколько часов)
   - Сделайте скриншоты из Marketplace

3. **Временные скриншоты для тестирования:**
   - Сделайте скриншоты интерфейса дополнения в Google Sheets
   - Используйте их для Store Listing
   - После публикации обновите скриншоты из Marketplace

## ❓ Часто задаваемые вопросы

### В: Могут ли тестовые пользователи установить дополнение через Marketplace?

**О:** Нет, при статусе "Testing" дополнение не видно в публичном Marketplace. Тестовые пользователи должны использовать ссылку на развертывание.

### В: Нужна ли верификация для тестирования?

**О:** Нет, верификация требуется только для статуса "In Production".

### В: Можно ли изменить статус обратно на "Testing"?

**О:** Да, можно, но это может повлиять на пользователей, которые уже установили дополнение.

### В: Сколько времени занимает верификация?

**О:** Обычно 3-7 рабочих дней, но может занять больше времени.

### В: Можно ли обновить дополнение после публикации?

**О:** Да, можно создавать новые версии развертывания и обновлять Store Listing.
